# 📱 تطبيق فاراماس للهاتف

تطبيق إدارة الصيدليات للهواتف المحمولة - يعمل على **Android** و **iOS**.

## 🚀 التثبيت والتشغيل

### المتطلبات
- Node.js 18+
- pnpm
- Expo CLI
- Android Studio (لـ Android)
- Xcode (لـ iOS - Mac فقط)

### الخطوات

```bash
# 1. انتقل لمجلد التطبيق
cd apps/mobile

# 2. تثبيت المكتبات
pnpm install

# 3. تشغيل التطبيق
npx expo start
```

### التشغيل على الجهاز

```bash
# Android
npx expo start --android

# iOS
npx expo start --ios

# متصفح الويب
npx expo start --web
```

## 🔗 ربط API

عنوان الخادم ثابت في البناء ولا يمكن تغييره من داخل التطبيق:

- نسخ التوزيع: `EXPO_PUBLIC_API_URL` في `eas.json` (حالياً `https://app.faramace.com/api`).
- التطوير المحلي: في `.env`، ثم أعد تشغيل Metro بـ `pnpm start --clear`.

```bash
EXPO_PUBLIC_API_URL=http://YOUR_SERVER_IP:3000/api
```

## 📦 بناء التطبيق

```bash

npx eas build --platform android
npx eas build --platform ios
```

## التحديثات التلقائية عبر Expo

- المشروع: https://expo.dev/accounts/risa02/projects/faramace
- النسخة المهيأة للتحديثات: `1.0.1` وما بعدها. النسخ الأقدم لا تحتوي آلية OTA، ويجب تثبيت APK الجديد مرة واحدة فوق النسخة القديمة، دون حذف التطبيق أو بياناته.
- قناة المستخدمين: `production`، وقناة التجربة: `preview`. بناء `production-apk` ينتج APK للمستخدمين بقناة `production`؛ بناء `preview` لا يستقبل تحديثات المستخدمين.
- فرع رفع النظام والهاتف الموحد هو `codex/release-readiness-fixes`. عند رفع تعديلات تشمل ملفات الهاتف أو الحزم المشتركة أو إعدادات بنائه إلى هذا الفرع، يعمل `.github/workflows/mobile-update.yml` تلقائياً: تثبيت التبعيات، اختبارات الهاتف، فحص TypeScript والتوافق الأصلي، ثم نشر EAS Update إلى قناة `production`. لا يلزم رفع الكود إلى فرع هاتف منفصل. انتظر نجاح المهمة في GitHub Actions.
- يعتمد النشر على سر المستودع `EXPO_TOKEN`. لا تضع قيمته في الكود أو ملفات البيئة المرفوعة.
- ينشر المسار عنوان API الإنتاجي `https://app.faramace.com/api` ويتجاهل ملفات `.env` المحلية. قِيَم `env` في `eas.json` تخص البناء ولا تنتقل تلقائياً إلى `eas update`؛ لذلك يحدد مسار GitHub العنوان صراحةً.
- يفحص التطبيق التحديث عند الفتح، ثم ينزله في الخلفية عند العودة للتطبيق أو كل 15 دقيقة أثناء الاستخدام. يطبق التحديث المحمّل تلقائياً عند العودة من الخلفية إلى واجهة آمنة مثل الرئيسية أو حول التطبيق، دون الحاجة لفرض الإيقاف. يُؤجل التطبيق إذا وُجدت فاتورة غير محفوظة أو شاشة إدخال مفتوحة، أو بدأ المستخدم لمس الواجهة أثناء التحقق. لا يعيد التشغيل لمجرد إسدال الإشعارات أو ظهور حوار نظام. يلزم اتصال بالإنترنت للتنزيل، وتظل النسخة الحالية تعمل عند انقطاعه.
- سياسة `appVersion` تربط التحديث بإصدار التطبيق الأصلي. يفحص `scripts/check-mobile-runtime.mjs` الإعدادات والتبعيات وملف القفل قبل النشر ويوقف OTA عند تغيرها. عند هذا التغيير: ارفع `expo.version`، ونفذ `node scripts/check-mobile-runtime.mjs --record` من جذر المستودع، ثم ابنِ ووزّع APK/AAB/IPA جديداً. يُعامل تغيير ملف القفل باحتياط كتغيير أصلي. تعديلات JavaScript/TypeScript والأصول المتوافقة تصل عبر OTA.
- مجلدا `android` و`ios` مولدان ومستبعدان من Git وأرشيف EAS؛ مصدر إعداداتهما `app.json` وإضافات Expo.

```bash
# من apps/mobile، مع حساب Expo مسجل الدخول
# اضبط EXPO_PUBLIC_API_URL=https://app.faramace.com/api وEXPO_NO_DOTENV=1 في بيئة الطرفية
pnpm build:production:apk
pnpm update:production --message "وصف التحديث"
pnpm update:preview --message "تحديث تجريبي"
```

لا تختبر وصول OTA بواسطة Expo Go؛ اختبر باستخدام APK مبني بقناة صحيحة وبصمة متوافقة. تأكد من بقاء سلة البيع أثناء تنزيل تحديث، ثم استخدم زر الرئيسية في الهاتف وافتح التطبيق من الأيقونة وتحقق من تشغيل التحديث تلقائياً إن لم يوجد عمل غير محفوظ. اختبر أيضاً أن العودة مع سلة غير فارغة لا تعيد التشغيل، وأن المسودة تُستعاد بعد إنهاء العملية. للاطلاع على التنزيلات والأخطاء استخدم لوحة EAS Update في المشروع.

عند اختبار إصدار تثبيت جديد، انشر تحديث OTA بعد اكتمال بنائه؛ التحديث المنشور قبل تاريخ الحزمة المضمنة قد لا يُعتبر أحدث منها. يعرض سجل Android الرسالة `[Faramace updates]` مع معرّف التحديث الجاري وقناة النشر، ويمكن استخدامه لإثبات وصول OTA وتشغيله فعلياً.

### حفظ مسودة البيع وحماية العودة للتطبيق

- يحفظ CheckoutContext أصناف السلة وكمياتها والأسعار الأصلية والمعدلة والعميل وطريقة الدفع والخصم والنقاط ومعرّف محاولة البيع محلياً باستخدام AsyncStorage. هذا حفظ مسودة فقط؛ لا ينشئ فاتورة في الخادم ولا يؤكد البيع تلقائياً.
- مفتاح المسودة منفصل لكل مستخدم وفرع؛ لا يُسمح بالتفاعل قبل اكتمال الاستعادة، ولا تُستبدل مسودة تعذرت قراءتها بفاتورة فارغة. تُرتب الكتابات لمنع رجوع بيانات قديمة بعد إفراغ السلة. يحتفظ الاسترجاع بمعرّف المحاولة لمنع تغيير مفتاح إعادة الطلب بسبب إعادة التشغيل وحدها.
- التحديث التلقائي يعمل فقط عند عودة حقيقية من background إلى active. يفحص سياسة المسار وسجل الشاشات وحراس النماذج المخفية، ثم ينتظر حفظ المسودة ويعيد الفحص قبل reloadAsync. أي تغيير أصلي ما زال يخضع لفحص native-runtime.
- على الشاشات الجديدة التي تحتفظ ببيانات إدخال في تبويب مخفي، استعمل hooks/useUpdateProtection.ts لمنع إعادة التشغيل أثناء الإدخال أو إرسال طلب. لا تضف شاشة قابلة للتحرير إلى قائمة المسارات الآمنة دون حارس.
