# مراسلة العملاء وجدولة رسائل WhatsApp

الميزة تنشئ حملة واحدة من أشخاص محددين أو صفحة أو جميع نتائج البحث، ثم تعالج رسائلها الفردية من طابور محفوظ في PostgreSQL. تعديل القالب ينشئ نسخة جديدة؛ تبقى نصوص الحملات السابقة محفوظة كما كانت عند التأكيد.

## الاستخدام

1. افتح **المرضى**، ثم **مراسلة العملاء** بجانب «إضافة مريض». الرابط موجود أيضًا تحت «العملاء والتوريد» في الشريط الجانبي. تبدأ الصفحة بسجل الرسائل والجدولة؛ القوالب في تبويب مستقل. للعودة استخدم **العودة إلى سجل المرضى**.
2. أنشئ مسودة، وأرسلها إلى Meta للاعتماد، ثم حدّث حالتها حتى تصبح «معتمد».
3. من سجل المرضى سجّل موافقة حصلت عليها فعلًا، مع دليلها. وجود الهاتف وحده لا يعد موافقة. يمكنك إلغاء الاشتراك من الزر نفسه.
4. حدّد أشخاصًا، أو الصفحة، أو نتائج البحث. الحد الحالي 1000 سجل للحملة؛ ضيّق البحث إذا تجاوزته.
5. اختر القالب، وأكمل المتغيرات، ثم عاين النص وعدد المؤهلين وأسباب الاستبعاد. تُستبعد الأرقام غير الصالحة والمكررة والتي لا تملك موافقة.
6. اختر **إرسال الآن** أو **جدولة لوقت لاحق**، وحدد التاريخ والوقت بتوقيت بغداد. تظهر المعاينة الموعد والتكلفة قبل التأكيد. تغيير الموعد يستلزم معاينة جديدة. التاريخ الماضي أو غير الصحيح يُرفض على الخادم أيضًا.
7. أكّد الإرسال. تُحفظ الرسائل والموعد في قاعدة البيانات. يتولى العامل إرسالها بعد حلول الموعد، ويستمر عند إغلاق الصفحة. النتائج في **الرسائل والجدولة**؛ تظهر حالة «مجدولة» قبل الموعد ويمكن إيقاف غير المرسل.

الإرسال يبدأ من إجراء واحد، ولكنه لا يصل إلى كل الهواتف في اللحظة نفسها. يعالج العامل رسالتين بالتوازي، وأربع رسائل كحد أقصى لكل تشغيل، لتقييد الطلبات ومدة التنفيذ.

المتغيرات المتاحة: `{{اسم_العميل}}`، `{{اسم_الصيدلية}}`، `{{نص_1}}`، `{{نص_2}}`. هذه نسخة للقوالب النصية فقط؛ لا تشمل المرفقات أو بوت محادثة. الصلاحية اختيارية ويمنحها المدير؛ لا يحتاج استخدام بقية النظام إلى تفعيل إرسال WhatsApp.

## كيف تعمل الجدولة

- الحقل `WaCampaign.scheduledAt` اختياري، ويُحفظ كوقت UTC في `TIMESTAMPTZ(3)`. الحقل الفارغ يعني إرسالًا فوريًا، لذلك تبقى الرسائل السابقة متوافقة.
- لا يعتمد التنفيذ على مؤقت في المتصفح أو بقائه مفتوحًا؛ الاستحقاق يُقارن بساعة قاعدة البيانات قبل حجز أي رسالة. يبدأ التنفيذ في أول دورة عامل بعد حلول الموعد؛ ليس هناك ضمان لتسليم كل الرسائل في اللحظة نفسها.
- الموعد جزء من بصمة المعاينة ومن محاولة الإرسال المحفوظة. إعادة الطلب نفسه تعيد العملية نفسها حتى لو مرّ موعدها؛ لا تُنشأ رسائل إضافية.
- تُثبت قائمة المستلمين والنصوص عند التأكيد. عند الموعد يُعاد فحص صلاحيات المنشئ والاشتراك ورقم المستلم والموافقة واعتماد القالب. إلغاء الموافقة أثناء الانتظار يمنع الإرسال.
- التكلفة المعروضة تقدير بالأسعار الحالية محفوظ مع الطلب؛ لا تضمن رسوم المزود في تاريخ لاحق. لا توجد محفظة أو خصومات مالية تلقائية في هذه النسخة.
- يُدار اتصال كل صيدلية مركزيًا من لوحة مدير المنصة؛ الربط الحالي يدوي، والتسجيل المدمج عبر Meta Embedded Signup ليس ضمن هذه النسخة.

## الصلاحيات والعزل

- `canManageWhatsAppTemplates`: إنشاء النسخ وطلب الاعتماد ومتابعته.
- `canSendWhatsAppCampaigns`: المعاينة والتأكيد والإيقاف والاستئناف الآمن.
- يلزم `canViewPatients` في الحالتين. تسجيل الموافقة يتطلب أيضًا `canEditPatient`.
- المالك والمدير مخولان افتراضيًا لإدارة القوالب والرسائل؛ الصيدلي والكاشير يحتاجان منحًا صريحًا. قراءة إعدادات الاتصال وحفظها محصوران بمدير المنصة `SUPER_ADMIN`، ولا تمنح صلاحية القوالب حق تعديل الربط.
- كل مؤسسة لها إعداد اتصال واحد وقوالب وموافقات وحملات منفصلة. الرقم لا يُربط بمؤسستين. الموظف المقيّد بفرع يرى مستلمي وحملات فرعه فقط.
- قبل كل رسالة، يعيد العامل التحقق من نشاط المنشئ وصلاحياته والاشتراك والمستلم ورقمه وموافقته واعتماد نص القالب لدى Meta.

## التفعيل على الاستضافة

الإرسال الفعلي **مطفأ افتراضيًا**. لا تستخدم اتصال إنتاج أو بيانات مرضى حقيقية في الاختبارات.

1. خذ نسخة احتياطية قابلة للاستعادة، وافحص وضع سلسلة الترحيلات وفق [دليل الترحيلات](database/migration-baseline.md). جرّب المرشح على قاعدة معزولة أولًا.
2. افحص الترحيلات التالية وطبّق غير المنفّذ منها قبل نشر الميزة:
   - `20261002120000_whatsapp_campaigns`
   - `20261002121000_whatsapp_attempt_aliases`
   - `20261002122000_whatsapp_attempt_resolution`
   - `20261005180000_whatsapp_pricing`
   - `20261006180000_whatsapp_scheduling`
     تخص جداول WhatsApp فقط، ولا تعدّل المبيعات أو المخزون أو الصندوق. لا تستبدل `migrate deploy` بـ `db push` أو تسجيل ترحيل لم يُنفّذ.
3. نفّذ البناء المعتاد للويب مع `prisma generate`. لا تولّد العميل فوق ملف محرك مستخدم من خادم تطوير يعمل؛ استخدم بيئة بناء منفصلة.
4. اضبط متغيرات الخادم الآتية في مدير أسرار الاستضافة:

| المتغير                   | وظيفته                                                                     |
| ------------------------- | -------------------------------------------------------------------------- |
| `WHATSAPP_ENCRYPTION_KEY` | مفتاح عشوائي 32 بايت بصيغة Base64 لتشفير بيانات الاتصال؛ ليس متغيرًا عامًا |
| `META_GRAPH_VERSION` | إصدار Graph API المختار في تطبيق Meta، بصيغة `vNN.N` |
| `WHATSAPP_WORKER_SECRET`  | سر عشوائي لا يقل عن 32 حرفًا لاستدعاء العامل                               |
| `WHATSAPP_SEND_ENABLED`   | يبقى `false` أثناء الإعداد؛ `true` بعد نجاح التحقق                         |

لا تستخدم بادئة `NEXT_PUBLIC_` لهذه الأسرار. احتفظ بمفتاح التشفير خارج المستودع مع نسخة آمنة؛ تغييره دون إعادة تشفير السجلات يمنع قراءة بيانات الاتصال. لا ترسله في المحادثة.

إذا ظهرت رسالة «حدد إصدار Graph API المدعوم في إعدادات الخادم»، فالطلب توقف قبل الاتصال بـMeta: إصدار API الفعلي مفقود أو لا يطابق صيغة `vNN.N`. يستخدم النظام `META_GRAPH_VERSION` وحده. تُزال المسافات المحيطة بالقيمة فقط، ولا يُستبدل الإصدار المفقود أو غير الصالح بإصدار آخر خفية. خذ رقم الإصدار من WhatsApp → API Setup في تطبيق Meta، واضبطه في `apps/web/.env` للتطوير المحلي أو متغيرات بيئة الاستضافة للنشر. إعداد المحلية لا يضبط Vercel. أعد تحميل خادم التطوير إذا لم يلتقط تغيير البيئة؛ وفي الاستضافة يلزم نشر جديد بعد تعديل المتغير. لا تضع رمز الوصول أو سر Meta مكان الإصدار، ولا تستخدم إصدارًا افتراضيًا غير متحقق منه لإخفاء الرسالة.

5. بحساب السوبر أدمن افتح **إدارة المؤسسات → تفاصيل المؤسسة وإجراءاتها → اتصال WhatsApp** (`/dashboard/admin/tenants`). أدخل `Phone Number ID` و`WhatsApp Business Account ID` ورمز الوصول و`Meta App Secret` للصيدلية المختارة. يراجع الخادم أن الرقم يتبع الحساب، ثم يشفر القيم. رمز الوصول يحتاج صلاحيات إدارة حساب WhatsApp وإدارة القوالب وإرسال الرسائل وفق إعداد تطبيقك لدى Meta. لا يدخل العميل هذه الإعدادات؛ تعرض صفحة مراسلة العملاء حالة التهيئة فقط.
6. اضبط عنوان Webhook الذي تعرضه الشاشة في Meta، مع رمز التحقق الذي يظهر مرة واحدة، واشترك في أحداث `messages`. عنوان HTTPS يجب أن يكون متاحًا لـ Meta دون حماية معاينة Vercel التي تتطلب تسجيل دخول. يُرفض POST إذا لم يطابق توقيع HMAC سر التطبيق، ولا تُعطّل التحقق لتجاوز خطأ الإعداد.
7. الربط في هذا الإصدار يدوي، ولكل مؤسسة عنوان Webhook خاص. عند ربط أكثر من صيدلية، خصص إعداد Meta الذي يوجّه أحداث كل حساب إلى عنوان مؤسسته؛ لا تستبدل عنوان تطبيق مشترك بين صيدليات دون ضبط توجيه أحداثها. التسجيل الموحد عبر Embedded Signup ليس ضمن هذا الإصدار.
8. شغّل عاملًا دائمًا كما أدناه، وجرّب رسالة إلى رقم اختبار موافق عليه، ثم تحقق من إشعار التسليم وإلغاء الاشتراك. لا يُعد نجاح البناء أو الاختبارات البديلة إثباتًا لوصول رسالة حقيقية.

## إدارة الاتصال من لوحة المنصة

- المسار الإداري `GET/PUT /api/admin/organizations/[id]/whatsapp` يتحقق من جلسة السوبر أدمن ودوره ونشاطه الحاليين في قاعدة البيانات. تُختار المؤسسة من عنوان المسار، ويُرفض تحديد مؤسسة أخرى في جسم الطلب.
- القراءة تعيد معرّفي الرقم والحساب ووقت التحديث فقط، دون الأسرار أو رمز التحقق. الحفظ والقراءة يمنعان تخزين الرد مؤقتًا. يُسجَّل الحفظ في سجل التدقيق داخل المعاملة نفسها دون أي سر.
- تعديل نموذج قديم بعد حفظ إداري أحدث يُرفض بـ409. استخدم زر تحديث الحالة ثم راجع البيانات وأعد إدخال الأسرار. كل حفظ يصدر رمز Webhook جديدًا يُعرض في نتيجة الحفظ فقط؛ حدّثه في Meta.
- تغيّر مكان الإدارة وصلاحياتها فقط؛ تبقى سجلات الاتصال الحالية كما هي في `WaConnection`، ولا يحتاج هذا النقل ترحيلاً جديدًا. مسار `action: connection` القديم في واجهة الصيدلية أصبح مرفوضًا على الخادم أيضًا.
- قبل تغيير الربط، أوقف الرسائل المنتظرة واحسم النتائج غير المؤكدة. التحذير في النموذج لا يوقف الطابور تلقائيًا، ولا يحتفظ هذا الإصدار بنسخة اتصال مستقلة لكل حملة.

## تشغيل العامل

مسار العامل: `GET /api/whatsapp/worker`. يُرفض الطلب بلا ترويسة `Authorization: Bearer ...` مطابقة لسر العامل. لا تضع السر في الرابط.

يتضمن المستودع `scripts/whatsapp-worker.mjs`. شغّله على جهاز استضافة أو خدمة تعمل دائمًا، تحت مدير عمليات يعيد تشغيله بعد التعثر، مع متغيرَي بيئة:

```text
WHATSAPP_APP_URL=https://YOUR_APPLICATION_DOMAIN
WHATSAPP_WORKER_SECRET=<نفس السر المحفوظ على خادم الويب>
```

```bash
node scripts/whatsapp-worker.mjs
# فحص تشغيل واحد:
node scripts/whatsapp-worker.mjs --once
```

يرسل طلبًا كل 10 ثوانٍ، ويرفض التحويلات إلى عنوان آخر، ولا يسجل أسماء أو هواتف أو رموز وصول. لا تشغّله داخل جلسة المتصفح أو وظيفة Vercel التي تنتهي بانتهاء الطلب. يمكن لخدمة جدولة أخرى استدعاء المسار بالترويسة نفسها؛ اختر التواتر بما يتوافق مع خطة الاستضافة وحدود Meta. لم تُضف هذه الميزة Cron تلقائيًا إلى مشروع Vercel.

## نتائج الرسائل ومنع التكرار

| الحالة               | المعنى والتصرف                                                     |
| -------------------- | ------------------------------------------------------------------ |
| `QUEUED`             | محفوظة، ولم يبدأ إرسالها. يمكن إيقافها                             |
| `SENDING`            | حُجزت للعامل قبل استدعاء المزود                                    |
| `SENT`               | قبلها المزود للإرسال؛ ليست إثبات وصول                              |
| `DELIVERED` / `READ` | إشعار تسليم أو قراءة موقع من Meta                                  |
| `BLOCKED`            | لم يُرسل طلب الرسالة بسبب فشل التحقق؛ عالج السبب ثم استأنف         |
| `FAILED`             | رفض المزود الطلب أو أبلغ بفشل التسليم؛ لا تعاد تلقائيًا            |
| `UNKNOWN`            | أُرسل الطلب لكن نتيجته غير مؤكدة، أو انقطع العامل؛ لا تعِد الإرسال |
| `CANCELLED`          | أُوقفت قبل بدء إرسالها                                             |

- تحتفظ الرسالة بمعرّف يربط إشعار المزود بالطلب حتى عند ضياع رده. لا تزعم الميزة ضمان التسليم مرة واحدة من المزود في كل ظرف؛ تختار عدم إعادة إرسال الطلب المجهول لحماية المستلم من التكرار.
- محاولة التأكيد تُحفظ في المتصفح قبل الطلب. فشل القراءة أو الحفظ يمنع الطلب. لا تمسح بيانات الموقع لمعالجة محاولة غير محسومة.
- عند ضياع الرد، استخدم «تحقّق من النتيجة وألغِ المحاولة إن لم تُسجّل»: يعيد الخادم الحملة المحفوظة، أو يغلق معرّف المحاولة تحت القفل نفسه الذي يستخدمه الإنشاء. بعد الإغلاق لا يستطيع طلب قديم متأخر إنشاء حملة بهذا المعرّف. فشل التحقق يبقي المحاولة محفوظة؛ هذه العملية لا تلغي حملة سُجّلت بالفعل.
- إعادة المحاولة بالمعرّف نفسه تعيد الحملة نفسها. محاولتان متطابقتان من المستخدم نفسه خلال دقيقة تُربطان بحملة واحدة، ويُحفظ ربط كل معرّف بها دائمًا. لا تبدأ حملة متطابقة مقصودة أخرى خلال هذه الدقيقة.
- الاستئناف يعيد `BLOCKED` فقط، بعد إعادة التحقق. لا يعيد `UNKNOWN` أو `FAILED`.
- الإيقاف يمنع الرسائل التي لم يبدأ إرسالها؛ لا يسترجع ما أُرسل ولا يضمن منع طلب جارٍ لحظة الضغط.
- قبل تغيير حساب Meta أو مفتاح الاتصال، أوقف الحملات المنتظرة واحسم الرسائل المجهولة لدى المزود. هذا الإصدار لا يحتفظ بنسخة اتصال مستقلة لكل حملة.
- إذا بقيت النتيجة مجهولة بلا Webhook، راجع حساب المزود؛ لا توجد أداة استنتاج حالة أو إعادة إرسال تلقائي لها.
- `STOP` و`unsubscribe` و`إيقاف` و`إلغاء` وما يقابلها دون همزة تلغي الموافقة على الرقم عند وصول رسالة موقعة. يلزم تسجيل طلبات الإلغاء خارج WhatsApp من شاشة الموافقة أيضًا.

## المحتوى والتكلفة

اعتماد القالب ورسومه وحدود الإرسال تحددها Meta. لا تعرض الميزة تقديرًا ماليًا غير موثوق، ولا تضمن اعتماد نص. يجب الحصول على موافقة التواصل واحترام الإلغاء. التسويق للأدوية والمنتجات الطبية يخضع لقيود خاصة؛ لا تستخدم الحملة العامة لترويج أدوية محظورة أو كشف تشخيص أو وصفة. راجع [سياسة WhatsApp Business](https://whatsappbusiness.com/policy/) قبل تفعيل رقم كل صيدلية، و[وثائق Cloud API الرسمية من Meta](https://www.postman.com/meta/whatsapp-business-platform/documentation/wlk6lh4/whatsapp-cloud-api) لإعداد الحساب والرسائل.

المسار القديم `/api/notifications/whatsapp` مغلق برد `410` للمستخدم المخول؛ انتقل إلى الحملات. جدول القوالب القديم محفوظ، ولا تُنسخ قوالبه كمعتمدة لدى Meta تلقائيًا.

## التحقق عند التحديث

شغّل اختبارات نطاق `whatsapp` والوحدات والتكامل على القاعدة المحلية المعزولة، وفحوص بصمات الترحيلات والعامل. ثم تحقق من واجهة الاختيار والمعاينة والقوالب والنتائج على البناء نفسه. اختبارات التكامل تستبدل Meta ولا ترسل رسائل حقيقية؛ يلزم اختبار الربط وإشعارات التسليم في حساب اختبار قبل الإرسال للعملاء.


## بقاء تطبيق WhatsApp Business على رقم الصيدلية (Coexistence)

تحقق من طريقة تسجيل الرقم قبل ربط رقم يستخدمه عميل في تطبيق الهاتف. إدخال Phone Number ID وWABA ID ورمز الوصول في فاراماس لا ينفذ Coexistence ولا يثبت تفعيلها. لا تطلب حذف حساب WhatsApp Business لتجهيز هذه الطريقة.

تتيح Meta عبر Embedded Signup ربط حساب WhatsApp Business الحالي مع استمرار المحادثات الفردية في تطبيق الهاتف، ومزامنة الرسائل مع Cloud API. يلزم التأهل كـTech Provider أو Solution Partner، وتسجيل مضمّن مع session logging، وWebhook يعالج history وsmb_app_state_sync وsmb_message_echoes وaccount_update، وبدء مزامنة البيانات خلال المهلة المحددة في وثائق Meta. بتاريخ المراجعة 2026-10-07 توصي الوثائق بالإصدار v4 لأن v2 وv3 يتوقفان في 2026-10-15. هذا إصدار تدفق التسجيل؛ لا يعني تغيير META_GRAPH_VERSION تلقائيًا.

**حد النسخة الحالية:** الربط يدوي؛ لا يوجد Embedded Signup أو مزامنة سجل المحادثات أو صندوق محادثات كامل في فاراماس. يعالج Webhook حالات التسليم وطلبات إلغاء الاشتراك، ولا يعرض الرسائل الواردة للموظف. هذه المتطلبات عمل لاحق وليست ميزات منفذة.

**آثار على التطبيق حسب Meta:** تستمر المحادثات الفردية والمكالمات، لكن تتغير بعض الميزات؛ تُعطّل قوائم البث، وتُفصل الأجهزة المرتبطة عند الانضمام ثم يمكن إعادة ربط الأجهزة المدعومة. رسائل التطبيق تبقى مجانية، ورسائل Cloud API تخضع لتسعير Meta. تحقق من أهلية الرقم فعليًا قبل تسجيله؛ قراءة الوثائق لا تثبت أهلية حساب بعينه.

للتحقق بعد الربط اطلب حقلي is_on_biz_app وplatform_type عبر خادم موثوق: true مع CLOUD_API يثبت تشغيل المسارين للرقم. اختبر رسالة من التطبيق ورسالة من النظام والرد، ولا تعد نجاح حفظ بيانات الاتصال إثباتًا لتزامن المحادثات.

**تسريع الإعداد:** خادم Meta الرسمي WhatsApp Business Tools MCP على https://mcp.facebook.com/whatsapp_business_tools يساعد في اكتشاف الحسابات والأرقام والقوالب والـWebhook بعد OAuth. وجود تعريفه المحلي لا يثبت اتصالًا أو منح صلاحيات، ولا يعوض تنفيذ مسار Coexistence. لا تعرض الأسرار في المحادثة؛ يُنشأ System User Token داخل إعدادات Meta.
